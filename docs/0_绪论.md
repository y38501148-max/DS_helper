# 绪论

## 数据结构

### 定义

课件中给出的定义是：

> 数据结构是一个二元组 $Data\text{-}Structure=(D,R)$。其中，$D$ 是数据元素的有限集合，$R$ 是 $D$ 上关系的集合。

其中：

- 数据元素之间的联系称为结构。
- 数据结构包括：数据的逻辑结构、数据的存储（物理）结构、数据的操作（算法）。

### 逻辑结构

- 线性结构：如线性表、栈、队列、串、文件等。
- 非线性结构：如树、二叉树、图、集合等。

### 存储结构

- 顺序存储结构：用一组地址连续的存储单元依次存放数据元素，数据间逻辑关系与物理关系一致。
- 链式存储结构：用一组地址任意的存储单元依次存放数据元素，数据元素之间的逻辑关系通过指针间接反映。
- 索引存储结构：利用索引关系确定数据元素的存储位置。
  - 特点：查找、插入和删除等操作的时间效率较高，但存储空间开销较大。
- 散列存储结构：通过散列函数与冲突处理方法确定数据元素的存储位置。
  - 特点：查找、插入和删除等操作的时间效率较高，主要缺点是确定好的散列函数比较困难。

### 基本操作

- 构造
- 检索
- 插入
- 删除
- 排序
- 遍历

## 算法

### 定义

课件中给出的三种表述：

> 算法是用来解决某个特定问题的指令的集合。  
> 算法是由人们组织起来准备加以实施的一系列有限的基本步骤。  
> 算法是一组解决问题的清晰指令，它能够对符合一定规范的输入，在有限的时间内获得所需要的输出。

### 算法的五个性质

- 输入：由算法的外部提供 $n\ge 0$ 个有限量作为算法的输入。
- 输出：由算法的内部提供 $n>0$ 个有限量作为算法的输出。
- 有穷性：算法必须在有限的步骤内能够结束。
- 确定性：组成算法的每一条指令必须有清晰明确的含义。
- 有效性：算法的每一条指令必须具有可执行性。

### 算法描述示例：求最大公因子

课件中的 C 函数如下：

```c
int comfactor(int m, int n) {
    int r;
    while (1) {
        r = m % n;
        if (r == 0) return n;
        m = n;
        n = r;
    }
}
```

## 算法分析

### 基本概念

- 时间复杂度：依据算法编写的程序在计算机中运行时间多少的度量。
- 空间复杂度：依据算法编写的程序运行时在计算机中占存储空间多少的度量。

课件强调：算法必须正确；在此前提下，再讨论时空效率。

### 频度统计法

一条语句的频度，是该语句被执行的次数。  
整个算法的频度，是算法中所有语句频度之和。

以语句执行次数作为算法时间度量的方法，称为频度统计法。

### 矩阵乘法示例

```c
#define M 1000
void MATRIX(int A[][M], int B[][M], int C[][M], int n) {
    int i, j, k;
    for (i = 0; i < n; i++) {
        for (j = 0; j < n; j++) {
            C[i][j] = 0;
            for (k = 0; k < n; k++) C[i][j] = C[i][j] + A[i][k] * B[k][j];
        }
    }
}
```

课件结论：算法频度为 $t(n)=n^2+n^3$，故时间复杂度为 $O(n^3)$。

### 大 O 表示法

若存在正常数 $c$ 和 $n_0$，使得对所有 $n \ge n_0$ 都有：

$$
t(n)\le c\cdot g(n)
$$

则称 $t(n)=O(g(n))$，$O(g(n))$ 称为算法的渐近时间复杂度。

补充：

- $O(g(n))$ 表示上界
- $\Omega(g(n))$ 表示下界
- $\Theta(g(n))$ 表示上下界相同

### 典型结论

- 只关注基本语句的执行频度，不必对每一步都做细算。
- 算式中的常数项和低阶项通常可以忽略，更关注最高阶项。
- 一般未特别说明时，时间复杂度默认指最坏时间复杂度。

### 常见时间复杂度

从低到高常见为：

$$
O(1) < O(\log_2 n) < O(n) < O(n\log_2 n) < O(n^2) < O(n^3) < O(2^n) < O(n!)
$$

## 本章应记住的结论

- 数据结构研究三件事：逻辑结构、存储结构、算法。
- 顺序存储强调“地址连续”，链式存储强调“指针连接”。
- 算法必须同时满足输入、输出、有穷性、确定性、有效性。
- 算法分析默认先保证正确，再比较效率。
- 时间复杂度本质上比较的是增长率，不是某次具体运行时间。
