# 查找

## 查找的基本概念

### 定义

> 查找是在查找表中确定某个特定记录存在与否的过程。

结果分两种：

- 查找成功：给出被查到记录的位置。
- 查找失败：给出相应信息。

### 查找表基本操作

- 查找
- 排序
- 插入
- 删除
- 修改

其中，课件强调：

> 插入、删除、修改都以查找操作为基础。

## 静态查找表与动态查找表

- 静态查找表：只做查询，不做插入、删除。
- 动态查找表：查找过程中需要插入不存在元素或删除已找到元素。

## 顺序表查找

## 顺序查找

### 思想

从第一个记录开始，依次与给定关键字比较，直到找到或扫描完全部记录。

### 算法

```c
int search(keytype key[], int n, keytype k) {
    int i;
    for (i = 0; i < n; i++)
        if (key[i] == k) return i;
    return -1;
}
```

### 平均查找长度

$$
ASL = \sum p_i c_i
$$

其中：

- `pi`：查找第 `i` 个记录的概率
- `ci`：查找第 `i` 个记录所需比较次数

### 结论

- 若查找概率相等，顺序查找时间复杂度为 $O(n)$。
- 优点：对表中元素排列顺序没有要求，原理简单。
- 缺点：查找效率低。

## 折半查找

### 适用条件

- 数据元素按关键字有序排列
- 必须采用顺序存储结构

### 思想

将待查关键字与当前查找范围中间位置记录比较：

- 相等：成功
- 小于：查前半部分
- 大于：查后半部分
- $low > high$：失败

### 非递归算法

```c
int binsearch(keytype key[], int n, keytype k) {
    int low = 0, high = n - 1, mid;
    while (low <= high) {
        mid = (low + high) / 2;
        if (k == key[mid]) return mid;
        if (k > key[mid]) low = mid + 1;
        else high = mid - 1;
    }
    return -1;
}
```

### 递归算法

```c
int binsearch2(keytype key[], int low, int high, keytype k) {
    int mid;
    if (low > high) return -1;
    else {
        mid = (low + high) / 2;
        if (k == key[mid]) return mid;
        else if (k < key[mid]) return binsearch2(key, low, mid - 1, k);
        else return binsearch2(key, mid + 1, high, k);
    }
}
```

### 判定树结论

课件结论：

> 折半查找成功的查找过程，正好等于在判定树上从根到该结点的一条路径。  
> 比较次数恰好是该结点所在层数。

### 复杂度

- 时间复杂度：$O(\log_2 n)$
- 平均查找长度近似：$\log_2(n+1) - 1$

### 优缺点

优点：

- 查找原理简单
- 查找效率高

缺点：

- 要求有序
- 只适用于有序连续顺序表
- 动态插入、删除代价高

## 插值查找

课件给出中点公式：

- 折半查找：$mid = low + (high - low)/2$
- 插值查找：$mid = low + (high - low)\cdot (k - a[low])/(a[high] - a[low])$

这是扩展内容，考试以理解思想为主。

## 动态查找表与 BST

课件总结：

- 无序表：顺序查找，插删方便，查找慢。
- 有序顺序表：可折半查找，查找快，插删慢。
- 有序链表：插删方便，查找仍只能顺序查找。

为兼顾动态插入与查找效率，引出二叉查找树。

### 课件中的“查找并插入”算法

```c
BTNodeptr searchBST(BTNodeptr p, Datatype item) {
    if (p == NULL) {
        p = (BTNodeptr)malloc(sizeof(BTNode));
        p->data = item;
        p->lchild = p->rchild = NULL;
    } else if (item < p->data) {
        p->lchild = insertBST(p->lchild, item);
    } else if (item > p->data) {
        p->rchild = insertBST(p->rchild, item);
    }
    return p;
}
```

## 索引

### 定义

> 索引是记录关键字值与记录存储位置之间的对应关系。

### 索引文件

> 由基本数据与索引表两部分组成的数据集称为索引文件。

### 索引表特点

1. 索引表由系统自动产生。
2. 索引表中表项按关键字值有序排列。

## 稠密索引

特点：

- 基本数据中的每一个记录在索引表中都占有一项。

课件结论：

> 在稠密索引文件中查找一个记录存在与否的过程，是直接查找索引表。

## 分块索引（非稠密索引）

特点：

- 将基本数据分成若干块
- 块间按关键字有序
- 块内可无序
- 每块在索引表中有一项，通常记录“最大关键字 + 首地址”

课件结论：

> 先查索引表确定所在块，再在相应块中查找目标记录。

## 多级索引

当索引本身很大时，可把索引再分块，建立“索引的索引”，形成树形结构的多级索引。

## Trie、B-树与 Hash

这一部分在课件后半段单独展开，主要针对大规模动态查找和外存查找。

## Trie

### 基本思想

课件把 Trie 归为“用键值的一部分来确定查找路径的树”。  
它来源于 `retrieval`，读作 `try`。

### 适用条件

课件明确给出 Trie 结构主要基于两个原则：

1. 键值由固定的字符序列组成，如数字串、字母串。
2. 对应结点具有分层标记。

典型例子：

- Huffman 编码：键值只由 `0`、`1` 组成
- 英文单词：键值只由 `26` 个字母组成

### 字典树特征

对于英文单词构成的字典树：

- 每个内部结点都有 `26` 个子结点
- 本质上是一个多叉树
- 树的高度等于最长单词长度

### 课件示例代码

```c
struct tnode {
    char isword;
    char isleaf;
    struct tnode *ptr[26];
};

void wordTree(struct tnode *root, char *w) {
    struct tnode *p;
    for (p = root; *w != '\0'; w++) {
        if (p->ptr[*w - 'a'] == NULL) {
            p->ptr[*w - 'a'] = talloc();
            p->isleaf = 0;
        }
        p = p->ptr[*w - 'a'];
    }
    p->isword = 1;
}

struct tnode *talloc() {
    int i;
    struct tnode *p;
    p = (struct tnode *)malloc(sizeof(struct tnode));
    isword = 0;
    isleaf = 1;
    for (i = 0; i < 26; i++) ptr[i] = NULL;
    return p;
}
```

### 性能结论

课件给出的结论比较直接：

- Trie 的树高只取决于最长单词长度。
- 对常用英文单词，通常访问 `5~7` 个结点就能完成查找。
- 若用理想平衡 BST 存 `10000` 个单词，树高约为 `14`，平均查找约访问 `13` 个结点。
- BST 查找时比较的是整个字符串；Trie 每一步通常只比较一个字母。

因此，课件结论是：

> 在访问速度要求很高的系统中，如拼写检查、词频统计中，Trie 结构是一个非常好的选择。

### Trie 在词频统计中的意义

课件把词频统计看成典型的动态查找表问题，其特点是：

1. 单词数量事先未知，规模可能很大。
2. 查找过程中频繁插入。

在这种场景下，Trie 是针对 BST 不够平衡、折半查找又不适用于动态插入时的一种更高效选择。

## B-树

### 背景

课件提出 B-树的出发点是：

> 对于一次不能加载至内存中的大数据（如数据库、文件系统），如何构造索引，使得以尽可能少的硬盘访问次数找到所要的数据。

因此，B-树属于面向外存的大规模索引结构。

### 定义

一个 $m$ 阶 B-树满足：

1. 每个分支结点最多有 $m$ 棵子树。
2. 除根结点外，每个分支结点最少有 $\lceil m/2 \rceil$ 棵子树。
3. 根结点最少有两棵子树；若根同时又是叶结点，则整棵树只有一个结点。
4. 所有“叶结点”都在同一层上，叶结点不包含任何关键字信息，可以视为外部空结点。
5. 每个分支结点包含如下信息：

   $$
   n,\ p_0,\ key_1,\ p_1,\ key_2,\ p_2,\ \ldots,\ key_n,\ p_n
   $$

其中：

- $n$ 为该结点关键字个数，且 $n \le m-1$
- $key_i < key_{i+1}$，其中 $1 \le i < n$
- $p_i$ 为指向第 $i+1$ 棵子树根的指针，$0 \le i \le n$

### 查找思想

课件说明：

- 先在当前结点的关键字集合中做顺序查找或折半查找；
- 若找到 $k = key_i$，则查找成功；
- 若 $k < key_i$，则沿指针 $p_{i-1}$ 继续查找；
- 重复直到成功，或者指针为空而失败。

这和 BST 的查找过程类似，但“每个结点内先查关键字，再决定走哪棵子树”。

### 课件代码

```c
keytype searchBTree(BNode *t, keytype k) {
    int i, n;
    BNode *p = t;
    while (p != NULL) {
        n = p->keynum;
        p->key[n + 1] = Maxkey;
        i = 1;
        while (k > p->key[i]) i++;
        if (p->key[i] == k) return p->key[i];
        else p = p->ptr[i - 1];
    }
    return -1;
}
```

### 插入原则

课件强调：B-树是从空树开始，逐个在叶结点中插入关键字而生成的。

若插入某关键字后，某结点关键字个数超过 $m-1$，则：

1. 以该结点“位置居中”的关键字为界，将该结点一分为二；
2. 产生一个新结点；
3. 将中间关键字插入双亲结点；
4. 若双亲也因此溢出，则继续向上分裂；
5. 最坏情况下分裂一直传到根，使树高增加 $1$。

这是课件要求掌握的核心结构性结论。

## B+树

### 定义

一个 $m$ 阶 B+ 树满足：

1. 每个分支结点最多有 $m$ 棵子树。
2. 除根结点外，每个分支结点最少有 $\lceil m/2 \rceil$ 棵子树。
3. 根结点最少有两棵子树；若根同时为叶结点，则整棵树只有一个结点。
4. 具有 $n$ 棵子树的结点中一定有 $n$ 个关键字。
5. 叶结点中存放记录关键字及指向记录的指针，或者存放数据块最大关键字及指向块的指针；并且叶结点按关键字大小顺序链接成线性链表。
6. 所有分支结点都可以看成“索引的索引”，结点中仅包含各孩子结点中的最大（或最小）关键字值以及指向孩子的指针。

### 与 B-树的区别

课件从结构上总结了三点：

1. B-树的每个分支结点中含有该结点关键字个数信息，B+树没有。
2. B-树的每个分支结点中含有指向关键字对应记录的指针，而 B+树只有叶结点含有这些记录指针。
3. B-树只有一个入口，即根结点入口；B+树有两个入口：
   - 一个指向根结点
   - 一个指向最左叶结点

### 使用场景

课件说明：

- B-树、B+树多用于文件系统或数据库系统索引。
- 它们本质上属于树形结构的多级索引。

## Hash（散列）

### 基本概念

课件把顺序查找、折半查找、索引查找、BST、Trie、B-树、B+树统称为“基于关键字比较的查找方法”，并指出：

> 散列查找追求的是不经过任何关键字值比较，或者只经过很少次比较就达到查找目的。

核心关系是：

$$
A = H(k)
$$

其中：

- $k$ 为记录关键字
- $H(k)$ 为散列函数（Hash 函数、杂凑函数）
- $A$ 为记录在查找表中的位置

### 散列冲突

若不同关键字 $k_i$ 与 $k_j$ 满足：

$$
H(k_i) = H(k_j)
$$

则称发生了散列冲突。  
课件把这样的两个关键字称为“同义词”。

### 什么是散列表

课件定义：

> 根据构造的散列函数与处理冲突的方法，将一组关键字映射到一个有限的连续地址集合上，并以关键字在该集合中的“像”作为记录的存储位置，按这种方法组织起来的表称为哈希表、散列表或杂凑表。

### 散列函数构造原则

一个“好”的散列函数应满足：

1. 定义域必须包括要存储的全部关键字；若表长为 $m$，则值域应在 $[0, m-1]$。
2. 计算出的地址应尽可能均匀分布。
3. 计算过程尽可能简单。

### 课件列出的构造方法

- 直接定址法
- 数字分析法
- 平方取中法
- 叠加法
- 基数转换法
- 除留余数法

其中课件重点展示的是除留余数法：

$$
H(k) = k \bmod p
$$

其中 $p$ 通常取不大于表长 $m$ 的素数。

### 冲突处理方法

#### 1. 开放地址法

课件给出的统一形式为：

$$
D_i = (H(k) + d_i) \bmod m,\quad i=1,2,3,\ldots
$$

其中：

- $H(k)$ 为散列函数
- $m$ 为表长
- $d_i$ 为地址增量

常见取法：

- 线性探测再散列：$d_i = 1,2,3,\ldots,m-1$
- 二次探测再散列：$d_i = 1^2,-1^2,2^2,-2^2,\ldots$
- 伪随机再散列：$d_i$ 取伪随机数序列

课件结论：

- 线性探测法容易产生“聚集”。
- 二次探测法能较好避免聚集，但不能探测到表中所有位置，至少能探测到一半。
- 开放地址法中的删除通常只能做逻辑删除，不能随意物理删除。

#### 2. 再散列法

形式为：

$$
D_i = H_i(k),\quad i=1,2,3,\ldots
$$

即冲突后改用不同散列函数继续找位置。

#### 3. 链地址法

课件思想：

- 将散列地址相同的记录链接成一个线性链表；
- 若散列范围为 $[0,m-1]$，则定义指针数组 `bucket[0..m-1]`，分别存放这些链表头指针。

### 装填因子与聚集

课件定义装填因子：

$$
\alpha = \frac{\text{散列表中实际存入的元素数}}{\text{散列表中基本区的最大容量}}
$$

意义：

- 一般有 $\alpha < 1$
- $\alpha$ 越大，散列表越满
- 它衡量的是散列表的“饱满程度”

课件指出，聚集的主要原因有两个：

1. 散列函数选择不合适
2. 负载因子过大

### 链地址法代码

```c
struct node {
    ElemType data;
    struct node *next;
};

struct node *Hashtab[NHASH];

struct node *lookup(ElemType key, int create) {
    unsigned int h;
    struct node *p;
    h = hash(key);
    for (p = Hashtab[h]; p != NULL; p = p->next) {
        if (p->data == key) return p;
    }
    if (create) {
        p = (struct node *)malloc(sizeof(struct node));
        p->data = key;
        p->next = Hashtab[h];
        Hashtab[h] = p;
    }
    return p;
}
```

课件还说明：发生冲突时，把新元素插到链表头部，算法更简洁、效率也更高。

### 字符串 Hash 函数示例

```c
enum { MULTIPLIER = 31 };

unsigned int hash(char *str) {
    unsigned int h = 0;
    char *s;
    for (s = str; *s != '\0'; s++) h = MULTIPLIER * h + *s;
    return h % NHASH;
}
```

课件还给出另一个针对字符串的写法：

```c
unsigned int hash(char *str) {
    unsigned int h = 0;
    while (*str != '\0') h = (h << 5) + *str++;
    return h % TableSize;
}
```

### Hash 的特点

链地址法的特点：

- 处理冲突简单
- 不会产生聚集
- 平均查找长度较小
- 适合事先难以确定表长的情况
- 删除操作简单

缺点：

- 指针域需要额外空间
- 当规模较小时，不如开放地址法节省空间

### Hash 的典型应用

课件明确列出：

- 编译系统中的符号表
- 浏览器中最近使用页面的维护
- 最近访问域名及其 IP 地址缓存

### 与词频统计的关系

课件最后用词频统计对比了几类方法：

- 折半查找 + 顺序表：查找性能为 $O(\log_2 N)$，但插入要移动数据
- 顺序查找 + 链表：查找性能为 $O(N)$
- BST：理想平衡时查找性能为 $O(\log_2 N)$
- Trie：查找性能与单词规模无关，只与单词平均长度有关
- Hash：查找性能与单词规模无关，只与 Hash 冲突数有关

并且课件给出一个总结性结论：

> 在各种查找方法中，只有散列查找法的平均查找长度 $ASL$ 与元素个数 $n$ 无关。

## 本章应记住的结论

- 顺序查找适用面广，但复杂度为 $O(n)$。
- 折半查找效率高，但只适用于有序连续顺序表。
- 动态查找表需要同时考虑查找、插入、删除三类操作。
- 索引本质是“关键字到地址”的对应关系。
- 稠密索引是“条条有索引”，分块索引是“块块有索引”。
- Trie 适合固定字符集的字符串查找，性能主要取决于键长。
- B-树、B+树是典型的外存多级索引结构，核心是“低层存数据，高层做索引”。
- Hash 查找的效率核心不在元素总数，而在散列函数质量与冲突控制。
